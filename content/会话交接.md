## 五、踩过的坑（改代码或重装前务必看）

1. **`.bat` 必须 GBK + CRLF** —— 中文 Windows 控制台是 936 代码页；UTF-8 或 LF 会让 cmd 解析错位（会出现 `setlocal` 变 `offsetlocal` 这类吞字符现象）。**`chcp 65001` 救不了**
2. **`.md` 必须 UTF-8 无 BOM + LF** —— 正好与 bat 相反，**别搞反**
3. **不要用 Word / WPS 打开 `.md`** —— 会生成 `~$` 锁文件并独占锁定；`build.mjs` 已加固为跳过这类文件
4. **`git` 不读系统代理，`gh` 会读** —— 会造成"建仓库成功、推送失败"；`一键推送.bat` 已内置自动读取系统代理
5. **`gh` 的 token 需四个 scope** —— `repo` + `read:org` + `gist` + **`workflow`**（缺 `workflow` 无法推送 `.github/workflows/`）
6. **GitHub Pages 不支持私有仓库**（免费计划）—— 故仓库已公开
7. **工作流不能自建 Pages 站点** —— 须先在 `Settings → Pages` 把 Source 选为 **GitHub Actions**（只能网页操作）
8. **Netlify 免费额度会耗尽并暂停生产构建** —— 已改用 GitHub Pages 作主通道；Netlify 站点仍在运行但停留在旧部署
9. **`build.mjs` 每次构建会清空整个 `site/`** —— 需要长期存在的静态文件必须写进构建脚本（如 `robots.txt`）

## 六、接手后怎么继续

1. **要改设定**：直接给内容。按既有流程处理 —— 核对与现有设定是否冲突 → 落地（原文逐字保留，改动写在整理层）→ 重建 → 死链检查 → 推送 → 验证线上
2. **要新增页面**：`content/` 放 `.md`，**并在 `build.mjs` 的 `NAV_GROUPS` 里登记**，否则不会出现在侧边栏（未登记的页面会被兜底归入一个「其它」分组）
3. **改完想固化**：说「打快照」，会生成 `archives\wiki-<日期>-<时刻>\` 并验证可完整恢复
4. **迁移后首次操作**：先跑一次 `一键推送.bat` 确认链路正常（它会构建、提交并推送）
